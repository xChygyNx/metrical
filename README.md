# metrical

Сервис сбора метрик и алертинга на **Go**. Проект состоит из агента, который собирает runtime-метрики, и HTTP-сервера, принимающего и хранящего их.

## Возможности

- Сбор метрик памяти и runtime Go через `runtime.ReadMemStats`, а также случайной метрики `RandomValue`.
- Сбор и отправка счётчика `PollCount`.
- Приём отдельных метрик и пакетов метрик через HTTP API.
- Сжатие HTTP-запросов и ответов с помощью **gzip**.
- Хранение метрик в памяти, с возможностью сохранять состояние в файл или PostgreSQL.
- Повторные попытки отправки при сетевых ошибках с экспоненциальной задержкой.
- HTTP-логирование и endpoints профилировщика `pprof`.

## Требования

- Go **1.22** или новее.
- Git.
- Для хранения в PostgreSQL — установленный и запущенный PostgreSQL.

## Быстрый старт

Склонируйте проект и загрузите зависимости:

```bash
git clone https://github.com/xChygyNx/metrical.git
cd metrical
go mod download
```

### 1. Запустите сервер

В первом терминале:

```bash
go run ./cmd/server -a localhost:8080 -f ./metrics.json -i 0
```

В этом примере метрики записываются в `metrics.json` синхронно при получении. Порт по умолчанию — `8080`.

### 2. Запустите агент

Во втором терминале из каталога проекта:

```bash
go run ./cmd/agent -a localhost:8080 -p 2 -r 10
```

Агент собирает метрики каждые 2 секунды и отправляет их серверу каждые 10 секунд. При штатном завершении агент также пытается отправить последние собранные значения.

### 3. Проверьте данные

Получить список метрик:

```bash
curl http://localhost:8080/
```

Получить значение конкретной метрики:

```bash
curl http://localhost:8080/value/gauge/Alloc
```

Пока агент не отправил первые данные, метрика может отсутствовать.

## HTTP API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/update` | Сохранить одну метрику из JSON |
| `POST` | `/updates` | Сохранить пакет метрик из JSON-массива |
| `POST` | `/update/{type}/{name}/{value}` | Сохранить метрику через параметры URL (совместимый старый формат) |
| `GET` | `/value/{type}/{name}` | Получить значение одной метрики в текстовом виде |
| `POST` | `/value` | Получить сохранённую метрику по JSON-запросу |
| `GET` | `/` | Получить список метрик, сгруппированных по типу |
| `GET` | `/ping` | Проверить доступность PostgreSQL |
| `GET` | `/debug/pprof/*` | Просмотр профилей Go runtime |

Типы метрик:

- `gauge` — значение с плавающей точкой; новое значение заменяет предыдущее.
- `counter` — целочисленный счётчик; поступившее значение прибавляется к текущему.

### Примеры запросов

Сохранить gauge:

```bash
curl -X POST http://localhost:8080/update \
  -H 'Content-Type: application/json' \
  -d '{"id":"Temperature","type":"gauge","value":21.5}'
```

Сохранить counter:

```bash
curl -X POST http://localhost:8080/update \
  -H 'Content-Type: application/json' \
  -d '{"id":"RequestCount","type":"counter","delta":1}'
```

Пример JSON для одной метрики:

```json
{
  "id": "Temperature",
  "type": "gauge",
  "value": 21.5
}
```

Пакетный endpoint `/updates` принимает массив таких объектов. Агент отправляет данные пакетами и использует gzip.

## Конфигурация

Настройки можно передавать аргументами командной строки или переменными окружения. Сервер также поддерживает JSON-файл конфигурации. В общем случае переменные окружения имеют приоритет над аргументами и настройками из файла.

### Сервер

| Флаг | Переменная окружения | Назначение | Значение по умолчанию |
| --- | --- | --- | --- |
| `-a` | `ADDRESS` | Адрес и порт HTTP-сервера, например `localhost:8080` | `localhost:8080` |
| `-i` | `STORE_INTERVAL` | Интервал сохранения метрик в файл, в секундах | `300` |
| `-f` | `FILE_STORAGE_PATH` | Путь к файлу с сохранёнными метриками | пусто |
| `-r` | `RESTORE` | Восстанавливать метрики из файла при старте | `true` |
| `-d` | `DATABASE_DSN` | Строка подключения к PostgreSQL | пусто |
| `-c`, `-config` | `CONFIG` | Путь к JSON-файлу конфигурации | не задан |

Если `-i 0`, сервер записывает метрики в файл при каждом обновлении. Если указан `DATABASE_DSN`, сервер подключается к PostgreSQL и автоматически создаёт таблицы для `gauge` и `counter`.

Пример запуска с PostgreSQL:

```bash
export DATABASE_DSN='postgres://metrical:metrical@localhost:5432/metrical?sslmode=disable'
go run ./cmd/server -a localhost:8080
```

Перед запуском создайте базу данных `metrical` и пользователя с соответствующими правами. Если `DATABASE_DSN` не задан, сервер использует внутреннее хранилище и может сохранять его состояние в файл.

### Агент

| Флаг | Переменная окружения | Назначение | По умолчанию |
| --- | --- | --- | --- |
| `-a` | `ADDRESS` | Адрес сервера в формате `host:port` | `localhost:8080` |
| `-p` | `POLL_INTERVAL` | Интервал сбора метрик, в секундах | `2` |
| `-r` | `REPORT_INTERVAL` | Интервал отправки метрик, в секундах | `10` |
| `-crypto-key` | `CRYPTO_KEY` | Путь к файлу публичного RSA-ключа агента | пусто |

Пример:

```bash
go run ./cmd/agent -a localhost:8080 -p 2 -r 10
```

**Примечание:** в текущей реализации агента переменная окружения `REPORT_INTERVAL` читается из `POLL_INTERVAL`. Чтобы надёжно задать интервал отправки, используйте флаг `-r`.

Путь к JSON-конфигурации агент получает через переменную окружения `CONFIG`. В файле поддерживаются поля `address`, `poll_interval`, `report_interval` и `crypto_key`.

## Хранение данных

- **В памяти** — метрики доступны до завершения процесса.
- **В файле** — параметр `-f` задаёт файл для сохранения состояния; `-i` определяет интервал записи. При `-i 0` запись синхронная.
- **PostgreSQL** — задаётся через `-d` или `DATABASE_DSN`. При подключении сервер создаёт таблицы `gauges` и `counters`.
